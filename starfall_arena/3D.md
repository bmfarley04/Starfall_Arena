# 3D.md

This document is the entry point for Starfall Arena's 3D implementation track.

Use it first whenever work is primarily about translating the current duel game from its existing 2.5D / orthographic presentation into a fuller 3D experience. You should be working in 3dscene, not in 3dtest.

Documentation location note:

- all 3D guidance docs live at the repo root
- do not look for `3D.md`, `3D_BUGS.md`, `3D_SYSTEMS.md`, `3D_COMBAT.md`, or `NETWORK.md` under `Assets/Scripts/3d`

## Purpose

The 3D effort is an implementation track for the same duel game, not a separate mode.

Default assumptions:

- preserve the duel-first structure and two-player combat focus
- preserve existing ship classes, weapons, abilities, augments, HUD expectations, and round flow unless 3D translation requires a real change
- preserve controller-first usability while keeping keyboard-and-mouse support working
- keep the 3D path aligned with the active networking direction in `NETWORK.md`
- treat PS4-class performance as a hard design constraint, not a cleanup task for later

## Non-Negotiable Rules

- For 3D-scoped code work, edit only `Assets/Scripts/3d` unless the user explicitly approves broader code changes.
- You may read non-3D scripts for reference, but do not silently edit them as part of a 3D task.
- If a 3D task needs a shared gameplay, UI, or networking change outside the 3D script tree, stop and ask the user before editing outside `Assets/Scripts/3d`.
- If a 3D change also changes shared game behavior, update the appropriate shared doc in addition to the 3D docs after getting permission when required.
- When a bug, regression, or recurring pitfall is found in the 3D translation layer, document it in the dedicated 3D bug notes instead of leaving it buried in task history.

## Routing Guide

- Working on 3D movement, flight feel, camera behavior, ship presentation, VFX support, or script placement:
  - read `3D_SYSTEMS.md`
- Working on 3D weapons, abilities, aiming, reticles, projectile logic, beam logic, or combat HUD expectations:
  - read `3D_COMBAT.md`
- Working on 3D Invasion, PvE waves, 3D enemies, enemy AI, or player-vs-enemy faction filtering:
  - read `3D_invasion.md` and `3D_AI.md`
  - also read `3D_COMBAT.md` and `3D_NETWORKING.md` when projectiles, damage, or network authority are involved
- Investigating a regression, architectural gotcha, or a bug that is specifically caused by the 3D translation layer:
  - read `3D_BUGS.md`
- Working on a 3D feature that adapts shared gameplay, UI, or networking behavior:
  - read the matching shared doc after the relevant 3D doc

## Documentation Rules

- Keep `3D.md` short. It should remain an index plus ground rules, not the place where subsystem details accumulate.
- Put current implementation details in the focused 3D sub-doc that owns that area.
- Put 3D-specific bug notes in `3D_BUGS.md`.
- If a focused 3D doc starts mixing multiple jobs again, split it before it turns back into another catch-all file.

## Current Constraints

The 3D path is still translating a game originally built around:

- `Rigidbody2D` gameplay
- a mostly planar duel space
- orthographic combat readability
- older 2D-era assumptions in movement, aiming, and VFX logic

Do not describe the 3D path as complete unless the relevant gameplay, UI, and networking flow is implemented end to end.
